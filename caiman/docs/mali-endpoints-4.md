# Caiman GPU19: MCU power and endpoint allocation

The r54p3 host source exposes no extra MCU power-permission write on this v11 G715. Pixel does power the SoC's TOP and CORES domains before using the GPU, and both reported on at gpu19 entry. The best next discriminator is a fresh, compute-only submission with live power sampling and separate group and stream status. The host source establishes the request protocol. Firmware's reason for withholding an endpoint remains unknown.

## Ranked causes

1. **Compute demand or dispatch setup.** gpu19 got GLB_ACK `0x0001000e`, CSG/CS START, and a successful command-stream STORE. Its post-STATUS_UPDATE snapshot has PC `0x1000a0` at RUN_COMPUTE, EP_CURRENT zero, EP_REQ `0x00070707` (compute 7, fragment 7, tiler 7 despite a tiler cap of 1), and CS_REQ_RESOURCE zero. Earlier host-powered runs also had zero endpoints. **Inference:** the group request word alone is insufficient evidence of live compute-iterator demand. Compare it with a STORE-only snapshot and a known-good compute packet, and check whether a one-core cap changes either status word. This probe samples READY after global init and after the stall. Its wait loop samples the result buffer and services JOB IRQ, so a brief power transition between the logged snapshots remains possible. [`probe-log-gpu19.txt:1028–1040`; `docs/gpu-plan.md:Step 5`; `probe/gpu.c:compute_prepare:391–421`; `probe/gpu.c:gpu_first_compute:436–464`; `csf/mali_kbase_csf_registers.h:CS_STATUS_REQ_RESOURCE and CSG_STATUS_EP_REQ:684–692,1336–1357`]
2. **Reset and loader fidelity.** The probe already matches the DT L2 hash writes and programs no coherency. It omits kbase's post-reset quirk replay and timestamp offset. The loader also omits the preboot trace and optional fault-counter backing. **Inference:** the outstanding bus-limit fields at `+0xf0c` are the most concrete unverified register difference. A nonzero reset value would give an actual configuration delta. Timestamp and trace backing are lower-priority checks. The source assigns no shader-power permission to these writes. [`probe/gpu.c:gpu_power_up:108–147`; `backend/gpu/mali_kbase_pm_driver.c:kbase_pm_init_hw:4475–4555`; `csf/mali_kbase_csf_firmware.c:kbase_csf_firmware_load_init:2626–2655`]
3. **SoC CORES domain or clock dropping after entry.** Holding TOP and CORES up is a real platform prerequisite. Both PMU status words were 1 before gpu19's reset, and earlier host-powered runs reached shader READY. **Inference:** startup domain power is unlikely to explain the common stall. Sample both status words again during RUN_COMPUTE to test retention. The GPU-local shader READY bitmap is a separate state. [`probe-log-gpu19.txt:981–982,1003–1007`; `docs/gpu-plan.md:Step 5`; `platform/pixel/pixel_gpu_power.c:gpu_pm_power_on_top_nolock:252–307`]
4. **Missing scheduler tick, firmware CONFIG gate, or MCU delegation.** The single-slot START already performs the applicable scheduler programming. The Pixel FW hook writes log verbosity, and explicit power delegation is gated off on tTUx. See the exact conditions below. [`csf/mali_kbase_csf_scheduler.c:scheduler_apply:4489–4553`; `platform/pixel/pixel_gpu.c:gpu_fw_cfg_init:131–140`; `backend/gpu/mali_kbase_pm_driver.c:kbase_pm_l2_update_state:2160–2197`]

## Reset, power and ownership writes

GPU offsets are relative to `0x1f000000`. GLB and CSG offsets below are relative to their interface pages.

| Register | r54p3 behavior on this target |
|---|---|
| `+0x50/+0x54/+0x58` PWR_KEY/OVERRIDE0/1 | Present in the regmap. The Pixel CSF init, quirk and PM paths reviewed issue no writes. The key and override pair in `platform/meson/mali_kbase_runtime_pm.c:89–90` belongs to Meson. |
| `+0xf00` CSF_CONFIG | Read after reset and replay. OR `0x100` only if `corestack_driver_control` is enabled for a platform that needs manual core-stack control. Kconfig defaults it off and documents older GPUs. The IDVS-size OR is also feature-gated and tTUx lacks the feature. The supplied Mali DT node has no quirk override. Use the reset readback with those gates off. |
| `+0xf04/+0xf08` SHADER_CONFIG/TILER_CONFIG | Read after reset and replay. The shader flags here are variation algorithm and TLS hash, with neither applicable to tTUx r1p3. The older T76x tiler clock-gate override does not apply. Preserve reset words. |
| `+0xf0c` L2_MMU_CONFIG | Write `old & ~0x0f000000` for tTUx with no DT override and no ACE. This clears the read and write bus-limit fields, because `KBASE_AID_32=0`. ACE alone adds snoop disparity. |
| `+0x304` COHERENCY_ENABLE | `0x1f` for no coherency, already written by the probe. DT and platform DMA coherency determine the selected mode. v11 uses this register. AMBA shareable-cache setup exits early and CSF skips the JM CCI snoop SMCs. |
| `+0x88/+0x8c` TIMESTAMP_OFFSET | On initial calibration write 64-bit zero, sample GPU TIMESTAMP `+0x98/+0x9c` and CPU time in timestamp ticks, then write 64-bit CPU minus GPU ticks. Subsequent init reapplies the cached offset. **Inference:** check timestamp increments for the system-timestamp timer experiment. The offset aligns time bases. |
| `+0x2c0/+0x2c4/+0x2c8`, `+0x48` L2_CONFIG | Write `0x36db6d/0x5b6db6/0`, set bit 24 while L2 is off. gpu19 read back `0x01140000`. PBHA propagation is feature-gated and absent on tTUx. |
| `+0x1a0/+0x1a4`, then `+0x700` MCU_CONTROL | Firmware-managed tTUx writes L2_PWRON `1/0`; wait for READY at `+0x160` and clear TRANS at `+0x220`. After AS0 UPDATE write MCU_CONTROL `2` (AUTO), with bit 31 clear. `+0x704` is read-only status. Bit 31 is doorbell-disable for the sleep protocol. `MCU_FEATURES +0x708` and `SHADER_PWRFEATURES +0x188` first appear in the v12 map. |
| `+0x820/+0x828` PWR_STATUS/PWR_COMMAND | Newer HOST_POWER interface. The real DELEGATE operation uses command field `0x20` for tiler and shader and, if present, neural before L2. kbase selects it via `KBASE_HW_FEATURE_POWER_CONTROL`, which tTUx lacks. The v11 sequence skips these addresses. |
| `+0x28` GPU_IRQ_MASK and `+0x24` GPU_IRQ_CLEAR | kbase clears mask bit 10 (POWER_CHANGED_ALL) after firmware takes over on legacy hardware. On enabling it, kbase first writes W1C `0x400` at `+0x24`, then sets mask bit 10. gpu19's raw-poll mask starts at zero. `0x600` RAWSTAT contains the two power-change bits, so clear/log the old latch before measuring fresh events. |

The live DT selects `adaptive`. Its scheduler PM flags are zero, so `firmware_hctl_core_pwr` is false. The firmware-managed initial mask is GLB in `+0x18/+0x1c = 0x01110055/0`; toggle GLB REQ bit 2 against ACK, ring bell 0, and compare. Core-attribute updates use the same bit 2 and, when changing the timer, bit 3 with `+0x14/+0x88`. The host completion predicate is equality under bits 2 and 3. These ACKs confirm consumption of the attributes. The GPU-local READY bitmap and CSG EP_CURRENT provide the separate power and allocation observations. GLB REQ STATE `[14:12]` is ACTIVE at zero, HALT at one, SLEEP at two, SUSPEND at three. Cold `global_init` leaves this field alone. Resume clears it to ACTIVE as required. gpu19's ACK has state bits zero. For the independent host-managed control, use TILER_PWRON `+0x190/+0x194 = 1/0` before MCU, zero GLB power-off timer, then SHADER_PWRON `+0x180/+0x184 = 0x01110055/0` after global ACK. Wait for stable READY and republish it with a fresh bit-2 transaction. ## Pixel platform and preboot CONFIG

- **SoC domains.** kbase init calls the power-on callback before reset if the GPU is off. Pixel attaches genpd devices by the DT names `top` and `cores`, then takes runtime-PM references in that order. The CORES domain depends on TOP. The Pixel PMU property is used for a locked status read, `exynos_pmu_read(0x1c84)` with mask `1`. For this board the probe reads TOP `0x15461a84` and CORES `0x15461c84` bit 0. For an off-domain port the source-backed operation is the two genpd gets, holding them through the workload. DT assigns TOP `cal_id=0xb1380000`, `need_smc=0x1ee10204`, and CORES `cal_id=0xb1380001` with no `need_smc`. The `need_smc` cell is platform data. The supplied GPU driver does not define the genpd provider's numeric SMC ABI or its register-write sequence. Separately, the guarded secure-rendering path calls `exynos_smc(SMC_PROTECTION_SET, 0, PROT_G3D, SMC_PROTECTION_ENABLE)` after the domain gets and the corresponding DISABLE on power-off. The protected-reset callback conditionally disables protection and then invokes generic reset. These calls concern secure rendering. The source supplies no SMC to authorize individual shaders or allocate endpoints. [`caiman-live.dts:pd_g3d and pd_embedded_g3d:2747–2767`; `platform/pixel/pixel_gpu_power.c:gpu_pm_power_on_top_nolock, gpu_pm_power_off_nolock, gpu_pm_callback_power_on, gpu_pm_get_power_state_nolock and domain init:252–307,342–367,418–422,685–698,742–800`; `platform/pixel/pixel_gpu.c:pixel_gpu_secure_mode_disable:97–121`; `backend/gpu/mali_kbase_pm_driver.c:kbase_pm_init_hw:4475–4505`]
- **CONFIG entries.** The type-1 payload records firmware VA, minimum, maximum, and name. Parsing registers metadata and leaves the image value intact. Pixel's registered hook finds `Log verbosity` and writes `0` to its firmware VA when present. The generic workaround hook writes the first DT `quirks-ext`/ `quirks_ext` u32 to the firmware VA for `WA_CFG0`; the supplied node has neither property. The numeric firmware VAs are entry data and cannot be derived from the C source. Runtime config update toggles GLB bit 9 after writing an updatable option. The preboot hook writes memory before AS0 load/MCU AUTO and needs no such doorbell. No mandatory CONFIG setting for scheduler admission or shader power was found in these paths. Pixel's `mcu_protm_scale` and `mcu_down_util_scale` are host DVFS tunables. [`csf/mali_kbase_csf_firmware.c:entry dispatch, kbase_csf_firmware_load_init and kbase_csf_trigger_firmware_config_update:1158–1177,2626–2655,3218–3245`; `csf/mali_kbase_csf_firmware_cfg.c:kbase_csf_firmware_cfg_option_entry_parse through kbase_csf_firmware_cfg_fw_wa_init:305–415`; `csf/mali_kbase_csf_registers.h:GLB_REQ_FIRMWARE_CONFIG_UPDATE:1540–1546`; `mali_kbase_config.c:kbasep_platform_fw_config_init:133–141`; `platform/pixel/pixel_gpu.c:gpu_fw_cfg_init and platform_funcs:131–140,323–335`; `platform/pixel/pixel_gpu_sscd.c:gpu_sscd_fw_log_init:701–711`; `platform/pixel/pixel_gpu_dvfs.c:DT utilization tunables:989–1006`; `caiman-live.dts:mali:5686–5724`]
- **Other preboot writes.** kbase initializes trace buffer backing before the platform hook. With an advertised page-fault counter pointer, it writes the VA of the final u32 of the MCU-write trace page into the advertised firmware pointer and zeros the counter. **Inference:** this is worth matching if a verified compute packet still stalls, especially if there is evidence of an MCU memory fault. It is instrumentation by host-source intent. [`csf/mali_kbase_csf_firmware.c:init_page_fault_cnt_firmware_memory and reinit_page_fault_cnt_firmware_memory:157–191`; `csf/mali_kbase_csf_firmware.c:kbase_csf_firmware_load_init:2626–2655`; `csf/mali_kbase_csf_trace_buffer.c:kbase_csf_firmware_trace_buffers_init:136–225`]

## One scheduling pass and ordered patch plan

`kbase_csf_scheduler_kick` only wakes the host scheduling thread when the tick timer is disabled. `scheduler_apply` suspends groups outside the run list, programs free slots, and updates priorities of resident groups. In this source the priority helpers are `update_resident_groups_priority` and `update_csg_slot_priority`. Equal priority returns without a write. For an actual change on v11, write the priority nibble at CSG in `+0x34[31:28]`, toggle CSG REQ bit 4 against ACK, and ring through GLB_DB_REQ. For a single clean slot use priority 15 in START and one ordered doorbell cascade after publishing INSERT, CS config, and CSG config. No tick-specific firmware command remains. STATUS_UPDATE bit 5 is a separate snapshot request. [`csf/mali_kbase_csf_scheduler.c:update_csg_slot_priority, program_csg_slot, update_resident_groups_priority, scheduler_apply and kbase_csf_scheduler_kick:2981–3037,3126–3209,3641–3660,4489–4553,7249–7265`; `csf/mali_kbase_csf_scheduler.h:kbase_csf_scheduler_invoke_tick:545–563`; `csf/mali_kbase_csf_csg.c:status update path:621–646`]

1. **Instrument the existing path.** Sample both PMU status bits before reset and during the stall. Log post-reset `0xf00–0xf0c`, confirm coherency/hash readback, and trace tiler and shader READY/TRANS during the wait. Read GLB fatal status/info at output `+0x10/+0x20/+0x24`, CS fault/fatal and REQ/ACK before acknowledging events, and GPU fault address as 64 bits. gpu19's MMU raw bit 17 appears by START, while both AS fault statuses and GPU_FAULTSTATUS are zero. CSF kbase decodes page faults only from MMU bits 15:0 and handles bus faults via GPU_FAULTSTATUS. Record bit 17 without diagnosing it as an AS1 bus fault. [`probe/gpu.c:gpu_faults, gpu_service, gpu_first_compute:281–288,424–464`; `probe-log-gpu19.txt:1031–1040`; `mmu/backend/mali_kbase_mmu_csf.c:kbase_mmu_interrupt:469–489`; `device/backend/mali_kbase_device_hw_csf.c:kbase_gpu_fault_interrupt:43–75`; `csf/mali_kbase_csf_registers.h:GLB_FATAL fields:274–277`]
2. **Run the demand control on a clean slot.** Capture an ACKed bit-5 snapshot with STORE alone, then submit compute with a fresh kick. On a separate clean START write compute mask `1/0` at CSG `+0x20/+0x24` (shader bit 0 is present), fragment `0/0` at `+0x28/+0x2c`, OTHER `0` at `+0x30`, and EP_REQ low/high `0xf0000001/0` at `+0x34/+0x38`. Keep the accepted global mask and timer settings. Compare EP_CURRENT/EP_REQ, CS `+0x4c` bit 0, PC and blocked reason after fresh status ACK. **Inference:** if demand remains unclear, prioritize a known-good RUN_COMPUTE packet and matching SPD/TSD, AS1 fetch permissions and queue/descriptor visibility. kbase's host source gives the interface contract and does not validate the probe's hand-encoded shader stream. [`probe/gpu.c:compute_prepare and gpu_first_job:391–421,534–628`; `csf/mali_kbase_csf_registers.h:CS/CSG registers:108–126,156–189,684–692,764–780`; `csf/mali_kbase_csf_scheduler.c:program_csg_slot:3126–3209`]
3. **Isolate the init deltas.** Apply the kbase quirk replay and timestamp setup before L2, starting with any actual difference in `+0xf0c`. Retain the gpu19 L2 setup and global transaction. If READY remains zero with demonstrated compute demand, compare against the full host-managed control and then reproduce the source-defined preboot metadata backing as a separate experiment. Treat 64 reported IDs, advancement beyond RUN_COMPUTE and clean fault status as the end-to-end success condition.
