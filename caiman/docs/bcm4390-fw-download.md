# BCM4390 B1 firmware download

Scope is first boot to a readable PCIe shared header, with the endpoint enumerated, BARs assigned, PCI memory decoding enabled, and sboot off. Source is Google's `2f66b21f`. **Unverified** identifies cross-version constants or missing definitions. Config offsets below are endpoint PCI configuration space. BAR offsets are MMIO.

1. **Apply the cold-start ASR workaround.** Issue these ordered 32-bit config writes: `0x80 ← 0x18018000` (PMU), `0x88 ← PCIE_SUBSYS_CTRL_BPACCESS_ENABLE`, `PCI_CFG_INDBP_ADDR ← PMU_REG_OFF(RegulatorControlAddr)`, `PCI_CFG_INDBP_DATA ← 0x0b`, `PCI_CFG_INDBP_ADDR ← PMU_REG_OFF(RegulatorControlData)`, `PCI_CFG_INDBP_DATA ← 0x12000`, `0x80 ← 0x18000000`, `0x88 ← 0x00080080` (last two values also measured). These are whole-word writes through config space, including the indirect PMU address/data pair. The three unresolved numeric definitions are the enable word, the indirect config pair, and the standalone PMU register pair. After core enumeration DHD also ORs `PCIE_BARCOHERENTACCEN_MASK` into config `0x88` for CA7. The measured ASR restore word alone does not establish that mask. (`dhdpcie_chip_specific_init`, `dhd_pcie.c:2527–2562`; `dhdpcie_dongle_attach`, 2618–2624, 2720–2736.)

   DHD's conditional CTO setup writes config `PCI_INT_MASK = PCI_CTO_INT_MASK | PCI_SBIM_MASK_SERR`, then writes PCIe-core `cpl_to_ctrl` through the fixed PCIe register aperture in BAR0. Use the measured `0x8a058000` if reproducing that setup. The numeric core-relative offset and config mask were unavailable in the matching headers. CTO is compile-time conditional and serves completion-timeout prevention. DHD also selects internal PCIe config register `0x4e0` through `ConfigIndAddr`, then reads and writes back `ConfigIndData` unchanged for the RAM aperture sizing workaround (**cross-version offsets** `0x120/0x124` relative to PCIe core). The shown `MaxResourceMask = 0x7fffffff` and force-HT sequence is for 4397 A0. The CA7 download branch has no D11 or additional PMU resource-mask write. Attach has watchdog/FLR, CLKREQ and bootloader scratch handling whose necessity on an already-up cold endpoint is unverified. The attach MPU workaround excludes 4390. (`dhd_pcie.c:2565–2599, 2751–2759, 2773–2859, 2418–2437, 8650–8658, 16846–16900`; [PCIe aperture helper in related DHD](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4398/+/refs/tags/android-16.0.0_r0.4/pcie_core_host.c); [PCIe indirect config offsets in upstream Linux](https://github.com/torvalds/linux/blob/master/drivers/net/wireless/broadcom/brcm80211/brcmfmac/pcie.c).)

2. **Keep ARM/SYSMEM accessible and enter download.** On the multibackplane build, DHD requests domain 1 before touching WLAN cores and around RAM accesses. On PCIe, RMW `BAR0 + PCI_16KB0_PCIREGS_OFFSET + CC_REG_OFF(PowerControl)` to set request bit 9 (`0x200`), then check status bit 17 (`0x20000`). The fixed PCIe aperture base is `0x2000` in related Linux C source; the numeric `PowerControl` offset remains unverified. The separate download-state power quirk targets PCIe revs 66/68. (`dhd_pcie.c:940–963, 2693–2695, 6276–6278, 11542–11576, 15105–15110`; `siutils.c:3259–3365`; [sbchipc.h, 4033–4065](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/2f66b21f47d4f6ab5bd87511c894b1782d04e742/include/sbchipc.h).)

   **Register routing.** Enumerate NCI from ChipCommon `EromPtrOffset` with config `0x80 = 0x18000000`. Resolve unit 0 for CA7 (`0x847`), SYSMEM (`0x849`) and PCIe2 (`0x83c`) from that table. On slice 0, `si_setcore` selects the core/APB mapping via config `0x80` and the interface node pointer via `PCIE2_BAR0_WIN2` (config `0x70` in older Broadcom `pcicfg.h`), with wrapper MMIO at `BAR0+0x1000`. For CA7 DMP control, temporarily set config `0x80` to `(EromPtrOffset & 0xfffffff8) & ~0x1fff`, then access `BAR0 + OOBR core descriptor offset + 0x08`. Restore config `0x80` afterward. Use the enumerated offsets and wrapper bases. The NCI DMP access uses OOBR, while `ai_core_cflags` uses AI wrapper `ioctrl`. (`siutils.c:1393–1423, 1544–1554, 1595–1603, 1899–1920`; `aiutils.c:520–545, 1390–1410`; [nciutils.c, 48–121, 489–506, 889–925, 1802–1855, 2572–2643](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/2f66b21f47d4f6ab5bd87511c894b1782d04e742/nciutils.c); [hndsoc.h, 205–213](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/2f66b21f47d4f6ab5bd87511c894b1782d04e742/include/hndsoc.h); [older pcicfg.h](https://android.googlesource.com/kernel/amlogic-tv-modules/dhd-driver/+/848138121a6d66498c71dde25d5c6adb34385126/bcmdhd-usb.1.363.110.17.x/include/pcicfg.h).)

   **State.** DHD checks SYSMEM at attach and resets it with `si_core_reset(0,0)` only if down on the normal path. For enter, program DHD BAR1 window to zero and, if mapped, DHD BAR2 window to zero. Check CA7 with `nci_iscoreup` (first wrapper IDM reset bit clear) and DMP bit 5 (`0x20`) set. The already-up, halted path needs no CA7 reset. Otherwise use `nci_core_reset(0x20,0x20)`: clear clock-enable/force-gated-clock flags, delay 1 µs and apply CPUHALT in DMP. Assert and poll IDM reset in reverse interface order, skipping shared PMNI, then set clock-enable and force-gated-clock, delay 1 µs and clear both. Deassert and poll IDM reset in reverse order, skipping shared PMNI and NIC400. Set both clock flags, delay 1 µs and clear force-gated-clock. The `idm_reset_control` is wrapper-relative via the second BAR0 window. **Unverified for this commit:** older NCI source puts this at wrapper `+0x140`, mask `0x1`. Finish enter by zeroing the last RAM word via BAR2. (`dhdpcie_check_reset_sysmem`, `dhd_pcie.c:2504–2525`; `dhdpcie_check_armca7_state`, 11615–11635; `__dhdpcie_bus_download_state`, 11712–11758; `dhdpcie_init_shared_addr`, 16054–16062; [nciutils.c, 2120–2320](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/2f66b21f47d4f6ab5bd87511c894b1782d04e742/nciutils.c); [older NCI layout](https://android.googleid.googlesource.com/kernel/google-modules/wlan/syna/dhd43752p/+/refs/heads/android-gs-pantah-5.10-android14/nciutils.c).)

3. **Download image and trailer through PCI BAR2.** DHD `DHD_PCIE_MEM_BAR1` is PCI resource 2, the 4 MiB BAR. DHD BAR2 is PCI resource 4. The Linux resource numbering is corroborated by related BCM4398 DHD. For each dongle address `A`, select `W = A & ~0x3fffff` in `PCI_BAR1_WIN` (config `0x84` in older DHD), then access `BAR2+(A-W)`. Split at `0x400000`. The first firmware byte at `0x2a0000` is at BAR2+`0x2a0000` with window 0. The last word at `0x5bfffc` is at BAR2+`0x1bfffc` with window `0x400000`. DHD hardcodes base `0x2a0000` and size `0x320000` for 4390 because the NCI RAM base and size queries were unsuitable. This assumes the default usable size equals physical size. (`dhd_pcie.c:2861–2881, 2995–3009, 6242–6344, 6825–6953`; [related BCM4398 resource mapping, 2039–2041](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4398/+/refs/tags/android-16.0.0_r0.10/dhd_pcie_linux.c); [older pcicfg.h, 67](https://android.googlesource.com/kernel/common/+/bcmdhd-3.10/drivers/net/wireless/bcmdhd/include/pcicfg.h).)

   - Copy `fw_bcmdhd.bin_4390_b1` to `0x2a0000` and save its first four bytes as the reset instruction. (`dhdpcie_download_code_file` and `dhdpcie_download_file`, `dhd_pcie.c:4416–4421, 4457–4459, 4500–4517`.)
   - Process `bcmdhd.cal_USI_G6BB_6327_V27` into NUL-separated vars using `process_nvram_vars`. Round the returned count up to 4, append a zero byte, then round that count up to 4 with zero fill. For resulting padded length `N`, write vars at `V = 0x5bfffc - N`, followed by LE32 `((~(N/4) & 0xffff) << 16) | ((N/4) & 0xffff)` at `0x5bfffc`. Keep the exact token for polling. If usable RAM is reduced, DHD computes the token length from `V` to the physical last word (or usable last word in remap mode). (`dhdpcie_download_nvram`, `dhd_pcie.c:4620–4657`; `dhdpcie_bus_write_vars`, 12563–12595, 12638–12671; [bcmutils.c, process_nvram_vars, 5411](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/2f66b21f47d4f6ab5bd87511c894b1782d04e742/bcmutils.c).)
   - Immediately below `V`, DHD always writes the RNG rTLV in the CA7 exit path. Ascending addresses contain padded random bytes, a 32-bit padded byte count with upper 16 bits zero, then the 32-bit RNG type. **Unverified for this commit:** 128 random bytes and type `0xfeedc0de` (older Broadcom entropy ABI), giving payload `V-0x88`, length `0x80` at `V-8` and type at `V-4`. The C source shows that DHD supplies the seed, but cannot establish that firmware requires it to boot. The END marker and signature records are under `FW_SIGNATURE`; FW trace is conditional on `DHD_FWTRACE`. No CLM bytes are staged by this boot path. (`dhd_pcie.c:11804–11830, 12095–12146, 12214–12221, 17660–17695`; [older bcmrand.h](https://android.googlesource.com/kernel/google-modules/wlan/syna/dhd43752p/+/3c566df7e7431f0a12544d0775121856cafdf87d/include/bcmrand.h).)

4. **Start CA7.** Select CA7 again. On the unsigned path DHD checks security status (or reads address 0 if status is unsupported) and writes the saved first four firmware bytes to **dongle address zero**, config `PCI_BAR1_WIN = 0`, PCI BAR2+`0`. With writes complete, RMW CA7's OOBR DMP control with `old & ~0x20`. CA7 is already out of reset at this point. DHD enables the boot interrupt before this RMW and selects PCIe2 again afterward. For a polling-only host, omission of interrupt setup is an inference from the driver's independent polling path and its use of the pointer even if the IRQ times out. (`dhdpcie_bus_write_flops`, `dhd_pcie.c:11654–11684`; `__dhdpcie_bus_download_state`, 11832–11835, 11917–11947.)

5. **Read the result.** Poll LE32 at `0x5bfffc` via BAR2 window `0x400000`. Firmware replaces the token with a dongle address. Reject zero, the saved token, `0xffffffff` and pointers outside RAM. Allow room for the header before reading it. DHD uses a 5,000 ms boot-IRQ wait for rev 133 and then reads the pointer even on timeout. Its ordinary silicon polling path uses 2,000,000 µs. A 5 s polling deadline is a bare-metal choice matching the IRQ budget. Follow the pointer using the same BAR2 translation. Print the first LE32 flags word and its low 8 bits as the version. **Cross-version layout**, consistent with DHD's field reads: offsets `+0x00 flags, +0x04 trap_addr, +0x08 assert_exp_addr, +0x0c assert_file_addr, +0x10 assert_line, +0x14 console_addr, +0x18 msgtrace_addr`. Assert/trap masks in the older ABI are `0x200/0x400`. The running image supplies the version and flags. (`dhdpcie_chip_support_fw_boot_intr`, `dhd_pcie.c:1067–1077`; `dhdpcie_wait_readshared_area_addr`, 14788–14888, 14925–14946; timeout at 714–720; `dhdpcie_readshared`, 15118–15172; [dhd.h, 3248](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/2f66b21f47d4f6ab5bd87511c894b1782d04e742/dhd.h); [older bcmpcie.h, 59–63, 137–146](https://android.googlesource.com/kernel/common/+/bcmdhd-3.10/drivers/net/wireless/bcmdhd/include/bcmpcie.h).)
