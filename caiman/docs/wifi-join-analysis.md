# BCM4390 WPA2-PSK join analysis

The highest-priority trial is to post the RX pool earlier and set firmware `bus:host_access=1` before the join. That reproduces a specific step in bcmdhd that the probe skips. The next trial is a raw 32-byte PMK with the stock ioctl buffer length. The reported event places the supplicant in the wait-for-M1 state at deauthentication. A zero host RX count cannot establish whether M1 arrived over the air, reached firmware, or was rejected before the state advanced. The probe counts only valid host RX completion types and IDs, and bcmdhd explicitly supports an in-dongle handshake. ## Connect setup

- **Supplicant enable and order.** bcmdhd preinit sets plain `sup_wpa=1` on interface 0 under `BCMSUP_4WAY_HANDSHAKE` when `dhd_use_idsup=1`. It treats `BCME_NOTREADY` as evidence of support on modular firmware, so check the returned status at actual connect time. The probe ORs the setters' statuses and proceeds even if a setter or the PMK ioctl fails. Upstream brcmfmac sets WPA version, auth, cipher and final AKM before enabling `sup_wpa`, then installs the PMK and joins. **Guess:** use that ordering as a controlled trial. The bcmdhd preinit call shows that enabling it earlier can also be intentional. (`probe/wifi.c:591–623`, `dhd_linux.c:1013–1018,12157–12170,13498–13510`, upstream `cfg80211.c:2457–2507,2579–2584`) [Upstream connect sequence](https://codebrowser.dev/linux/linux/drivers/net/wireless/broadcom/brcm80211/brcmfmac/cfg80211.c.html#2457)
- **PMK ABI.** The supplied header puts little-endian `key_len` at byte 0, `flags` at 2, `key[256]` at 4, `opt_len` at 260 and optional TLVs at 262. The probe sends the complete 262-byte fixed prefix and uses the defined passhash flag. The indexed public Caimito `wl_cfg80211_connect` excerpt under `WL_PSK_OFFLOAD` instead copies the raw PMK from `sme->crypto.psk`, sets flags to 0, and sends a zeroed `sizeof(wsec_pmk_t) + 1` buffer. Use that exact size from the matching header. With a true flexible-array member and two-byte struct alignment, that is 263 bytes. Verify `sizeof` in the actual build before hardcoding it. **Guess:** a raw PMK bypasses any firmware passphrase/SSID handling difference. The 262-byte fixed prefix alone gives no evidence that firmware rejected the ioctl. Try raw 32 bytes with zero flags and zero optional length. Record only command status and keep key material out of diagnostics. (`wlioctl.h:2460–2487`, `wlioctl_defs.h:966`, `probe/wifi.c:572–583,606–615`) [Google BCM4390 PSK-offload source](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/%2B/refs/heads/android-gs-caimito-6.1-android14-qpr3-d1/wl_cfg80211.c)
- **RSN, IEs and MFP.** Inspect the actual STA association request and BSSID selected. The probe looks for RSN in event 7 data. The ABI also provides request/response lengths via `wl_assoc_info_t`. Upstream gets `assoc_info`, `assoc_req_ies` and `assoc_resp_ies` and sets `wpaie` from the selected WPA/RSN element plus separately programmed association-request vendor IEs. These reads can distinguish the transmitted policy from the scan result. For a plain CCMP/PSK AP, check the STA advertises PSK and a compatible pairwise/group cipher and PMF policy. **Guess:** if the STA RSN is absent or mismatched, program a STA RSN IE for the selected policy via `wpaie` before connect. Avoid copying the AP's entire RSN advertisement. Test per-BSS `mfp` after `wsec` only if the actual RSN policy calls for it. Upstream derives the MFP setting from RSN capabilities before the final AKM write. The ABI distinguishes PSK `0x80` and PSK-SHA256 `0x8000`. The effect of these knobs on this firmware's M1 path is unverified. (`probe/wifi.c:297–310`, `wlioctl.h:2607–2615`, `wlioctl_defs.h:645–657`, upstream `cfg80211.c:2213–2245,2416–2440,6332–6373`) [Upstream STA security and IE handling](https://codebrowser.dev/linux/linux/drivers/net/wireless/broadcom/brcm80211/brcmfmac/cfg80211.c.html#2213)
- **Join and interface selection.** Start with the primary interface and record both `ifidx` and `bsscfgidx` from the event, as stock does. The probe sends interface 0 in the ioctl header. A per-BSS iovar has wire form `bsscfg:<name>\0` followed by the 32-bit BSS index and payload. That index is distinct from the msgbuf interface field. **Guess:** try a BSSID/channel-pinned `join` using the ABI version accepted by firmware and the scan chanspec. The local header defines several extjoin versions and their fixed lengths. Upstream uses per-BSS `join` with BSSID/channel and falls back to SET_SSID, so a successful SET_SSID association alone gives no basis to require the alternate entry point for offload. (`probe/wifi.c:165–179,367–407,619–623`, `bcmevent.h:73–87`, `dhd_common.c:2073–2100,5170–5172`, `wlioctl.h:1904–1951`, upstream `cfg80211.c:2523–2606`) [Upstream join and fallback](https://codebrowser.dev/linux/linux/drivers/net/wireless/broadcom/brcm80211/brcmfmac/cfg80211.c.html#2523)
- **Other knobs.** Stock configures `roam_off`, PM and frameburst as preinit policy. `sup_wpa_tmo` has no verified setter or ABI in the supplied connect evidence. **Guesses, lower priority:** read it if supported, and test `PM_OFF` or disable roaming one at a time if there is evidence of a timing or BSSID-selection issue. Leave frameburst at the baseline for initial isolation. The firmware-preinit frameburst default in the cited path is 1. (`dhd_linux.c:13157–13174,13265–13269,13390–13410,13498–13510`, `wlioctl_defs.h:781–782,2477`)

## Full-dongle RX and IPC

- **Host access and pool.** Stock gets firmware `rxbufpost_sz` as a 16-bit result, applies a fallback and size checks, posts RX buffers, then sends `bus:host_access` and runs firmware preinit. It sets host access to 1 in the normal path. Under `WLAN_ACCEL_BOOT` it sets 0 and defers enabling access to the cfg layer. `max_host_rxbufs` is read as a pool target, with legacy fallback 256 if zero. The host refills toward its target and tracks outstanding buffers. It is not a host setting to overwrite. The reference provides no minimum of 32 for this firmware. **Guess:** a missing access enable, an incompatible buffer length, or unconsumed posts could explain the absence of host data. A direct link between that gate and internal EAPOL handling is unverified. (`bcmpcie.h:381–385`, `dhd_msgbuf.c:117–118,4662–4669,6160–6175,6258–6301,6579–6600`, `probe/wifi.c:133–137,603–605`)
- **Common rings and work items.** Keep H2D ring 1 as 32-byte RX posts and common ring 4 as 40-byte RX completions for this non-aggregated rev-9 setup. The probe's offsets for post length/address and completion length/offset match the structs. Stock switches the legacy completion size only for pre-rev-7 and has separately negotiated rev-9 aggregation. The 20-byte `_V3` item belongs to the alternate work-item family. Stock puts if_id 0, a packet ID, modulo-253 epoch and the ring phase into each post and supports zero metadata. The probe matches the initial phase of zero and epoch of one but never toggles the phase on wrap. The host cap does not opt into H2D valid-phase checking. This wrap difference cannot explain the first 32 posts. (`bcmpcie.h:182–192,450–452`, `bcmmsgbuf.h:60–61,86–101,1027–1094,1734–1803`, `dhd_msgbuf.c:2122–2132,3813–3846,4199–4210,4399–4435,4842–4850,6605–6638,7020–7039`, `probe/wifi.c:123–137,197–218,225–235,427,434–437`)
- **Index and completion visibility.** With the supplied flags, DMA indices and the XORCSUM flag are advertised. The 2-byte index flag is clear, so the probe's 4-byte strides are consistent. The probe publishes both DMA and TCM indices. Stock chooses its index path and flushes the descriptor before making the producer visible and ringing DB0 in the ordinary path. Verify that the DMA window is actually coherent or uncached, or apply the appropriate cache clean/invalidate and ordering. Use the firmware H2D RX-post consumer and D2H RX producer in both locations before interpreting zero frames. Stock selects completion synchronization from the negotiated mode and has a special case for XORCSUM. The probe always waits on the header epoch and then consumes even if the wait expires. Match the negotiated completion readiness check, or at minimum log and stop at an unready/invalid item. Decode ring status reports with request ID, status, ring ID and write index. (`bcmpcie.h:64–79`, `dhd_pcie.c:15068–15074,15182–15185,15233–15239,15331–15360,15601–15627`, `dhd_msgbuf.c:1773–1838,2095–2116,8949–8959,13751–13813`, `probe/wifi.c:199–250,349–355,440–453,639–640`)
- **Payload offset and safe reads.** Stock reads shared `dma_rxoffset` and uses it as a fallback when the per-completion data offset is zero. This changes where Ethernet parsing starts once a completion exists. The probe uses only the completion offset and logs a source MAC even for short payloads. Check status, request ID, minimum Ethernet length and offset/length bounds before reading. (`dhd_pcie.c:15157–15168`, `dhd_msgbuf.c:8108–8125,8403–8413`, `probe/wifi.c:233–246`)
- **Flow rings, mailbox and info rings.** The common RX rings are initialized and stocked independently of per-peer TX flow-ring creation. A host TX flow ring is for host transmissions and the source gives no evidence that the firmware's internal supplicant needs one for M1 or its reply. Host-ready is already sent by the probe. The shared mailbox flag is clear for the supplied flags, and that selector concerns sleep/D3 handshakes. `flags2=0x4de43001` advertises EDL/debug-buffer support. Those features concern debug traffic and are separate from the common RX path. The Android log confirms EDL allocation only. Start the RX investigation on the existing common rings. (`bcmpcie.h:98–113,143–145,182–192,387–389`, `dhd_msgbuf.c:4838–4852,6298–6301,10020–10062,14695–14773`, `dhd_pcie.c:6540–6592,15303–15314,16457–16473`, `probe/wifi.c:434–462`, `docs/android-dhd-dmesg.txt:31–35`)

## Trial results 2026-11-19 and next steps

The two changes from the earlier report shipped in the same trial. Firmware accepted `bus:host_access=1`, all five security settings, the 32-byte raw PMK, and SET_SSID. Authentication and association succeeded and the security readbacks matched. Firmware consumed all 32 RX posts, while the D2H RX producer stayed at zero in both index locations. This establishes descriptor consumption and zero published host RX completions for the attempt. The internal EAPOL path can consume or discard a frame before msgbuf, so neither index reports whether the AP sent M1 or whether the radio received it. Event 46 reports that the supplicant was still in WAIT_M1 when firmware received deauth (supplicant reason 14, `WLC_E_SUP_DEAUTH`). Event 6 then reports peer reason 15, four-way handshake timeout, at the end of the ~9.8 s attempt. The firmware's own supplicant M1 timeout is a different event-46 reason, 16. A simple PMK mismatch normally first affects the AP's validation of M2, since M1 has no MIC to validate with the PMK. The accepted PMK ioctl establishes provisioning status only. (`probe-log-wifi13.txt:1755–1779`, `wlioctl_defs.h:2855–2877`, `bcmevent.h:611–629`, `dhd_msgbuf.c:8108–8125,8403–8413`)

### Association and likely explanations

- The transmitted RSNE shows version 1, one CCMP-128 group suite, one CCMP-128 pairwise suite and one PSK AKM (00:0f:ac:02). LE capabilities `0x008c` set MFPC, clear MFPR and encode the maximum PTKSA replay-counter capability field (bits 2–3 both set). Association success establishes acceptance of that request, while the AP's RSNE, actual BSSID and negotiated link configuration still matter. Read `assoc_info`, `assoc_req_ies` and `assoc_resp_ies` during the interval after association. Use bounds of 250 request IE bytes and 316 response IE bytes for the logged lengths (subtract the 4- and 6-byte fixed bodies respectively, plus 6 request bytes only on reassociation), further limited by the actual reply size. The current loop uses the full request length and the final two `0/0` entries are consistent with the four extra bytes of zero fill. Capture event peer MAC, `ifidx`, `bsscfgidx` and `WLC_GET_BSSID` (23, six result bytes) during that interval. (`probe-log-wifi13.txt:1764–1779`, `probe/wifi.c:670–697`, `wlioctl.h:2607–2615`, `802.11.h:289,303`, `bcmevent.h:73–87`, `wlioctl_defs.h:716`)
- **IE identities are guesses until the extension octets are recorded.** EID 255 puts the extension ID at the first body byte. `255/33` is consistent with HE Capabilities (35/0x23), `255/18` is consistent with EHT Capabilities (108/0x6c), and `255/2` is too short for a Basic Multi-Link element containing its control, common-info length and MLD MAC. Lengths alone cannot identify any of the three. Check for 106/0x6a (EHT Operation), 107/0x6b (Multi-Link) and 108/0x6c on both sides. For 107, decode the LE16 control immediately after the extension ID (low three bits zero for Basic), then the common-info length and MLD MAC, followed by any bounded per-STA profiles. Compare requested profiles to accepted response profiles and operative links. EHT capability and even Basic ML signaling alone do not establish multiple operative links. (`802.11.h:1573–1576,1635–1644`, `wlioctl.h:20431–20460`, `probe-log-wifi13.txt:1777–1779`)
- **Highest-priority firmware configuration difference.** The public Caimito driver gates MLO on host support and an AKM allowlist. Plain WPA2-PSK falls through the unsupported case. It calls `wl_mlo_sta_config` before connect and sends a configuration subcommand to `mlo`. The Android `mlo_sta_disable` module parameter short-circuits the helper and is a host variable. The indexed sources also show raw PMK provisioning under `WL_PSK_OFFLOAD`, consistent with trial 13, and a BSS-scoped `sup_wpa` write in an FT-specific branch. Local DHD preinit sets plain `sup_wpa=1` under its internal-supplicant build/runtime gates. The public source was available through indexed excerpts, so Google file line numbers and the actual device build flags are unverified. (`dhd_linux.c:1013–1018,13498–13510`, `wlioctl.h:20250–20265,20316–20342`) [Google BCM4390 wl_cfg80211.c, wl_is_mlo_sec_supported, wl_mlo_sta_config and connect](https://android.googlesource.com/kernel/google-modules/wlan/bcmdhd/bcm4390/+/refs/heads/android-gs-caimito-6.1-android14-qpr3-d1/wl_cfg80211.c)
- **Failure mechanisms to distinguish.** The AP may have withheld M1, transmitted it without delivery or acknowledgment, or sent it to an address/link the firmware did not associate with this supplicant. If ML was actually negotiated, link selection, per-link power state and MLD versus link MAC/BSSID demultiplexing are plausible firmware interoperability faults. On a legacy association, ordinary STA power save and RF delivery remain plausible. An AP-side trace would distinguish no M1, repeated unacknowledged M1, acknowledged M1 without M2, and a handshake that progressed on air. For an MLD, compare wire transmitter/receiver addresses and channel against the association link and operative profiles before drawing conclusions. Firmware EAPOL forwarding is another hypothesis. A straightforward host handoff would normally yield a host completion if delivery succeeds, whereas this trace reports WAIT_M1 and zero completions. The stock host's conditional EAPOL handling covers specific cases such as post-roam M1 and provides no evidence of a required initial-join host EAPOL step with IDSUP enabled. (`wlioctl.h:20254–20261,20285–20309,20431–20460`, `dhd_linux.c:8058–8061,13498–13510`, `probe-log-wifi13.txt:1769–1776`)

### Event 46 payload

The payload is exactly 30 bytes, a vendor IE (`dd`, length `1c`) with Broadcom OUI `00 90 4c`, subtype `39` (57), LE16 timing version 1, and two zero alignment bytes. The following five fields are LE32 microseconds. The final two printed bytes at offsets 30–31 fall outside `datalen`. DHD searches this same OUI/subtype and verifies length and version. ### What the local DHD does before ordinary RX

1. PCIe shared discovery reads LE32 `dma_rxoffset` and saves it in the protocol context. The version mask `0xff` gives firmware revision 9 for `0x70250109`. Protocol init negotiates host capability words, publishes negotiated DMA index addresses, then initializes the five common rings through their shared descriptors. The ordinary H2D RX post ring is 1 with 32-byte items and the ordinary D2H RX completion ring is common ring 4 with 40-byte items. The 32-byte RX completion stride is only for pre-rev-7. Init also establishes sync, scratch DMA and host-ready, allocates the TX flow-ring pool, and posts ioctl response and event buffers. Pool allocation reserves host memory for later TX ring creation. (`bcmpcie.h:55,182–192`, `bcmmsgbuf.h:86–100`, `dhd_pcie.c:15157–15168`, `dhd_msgbuf.c:3813–3854,4800–4899,4940–4941`, `probe-log-wifi20.txt:1764`)
2. The H2D control message `MSG_TYPE_D2H_RING_CREATE` is used for additional rings. For the rev-6+ info path when eligible, DHD sends a D2H debug-buffer completion create, then an H2D debug-buffer submission create referencing that completion ID. Init logs info-ring failure and continues. EDL and other specialized rings have their own feature gates. Ordinary ring 4 was already initialized before these calls and requires no create message at rev 9. TX flow creation is tied to host TX flow setup. The DHD RX post and completion paths carry packet IDs and interface information independently of a prior host TX flow. (`dhd_msgbuf.c:4838–4852,4960–5033,5503–5526,6605–6638,8270–8413,13964,14755–14773`, `dhd_pcie.c:6540–6592,16463–16475`)
3. After `dhd_prot_init`, dongle synchronization posts timestamp buffers and queries WLC version. In the size-query path it GETs `rxbufpost_sz` as a LE16 size, with a compile-time fallback and upper bound, and platform alignment for allocation. The alternate posting build assigns the default plus `BCMEXTRAHDROOM`. The local source refers to the default size macro without supplying its definition. The posted packet length can differ from allocation size. DHD fills toward the shared `max_host_rxbufs` target (fallback 256 if zero), posts data buffers, then sends `bus:host_access` as LE32 1 in the ordinary build before preinit. The accelerated boot path sends 0 and defers enablement to cfg. The probe already posts 32 × 2048-byte buffers and enables host access successfully. No extra `bus:rxbufpost` write appears in this sequence. (`dhd_linux.c:10519`, `dhd_msgbuf.c:4663–4669,6160–6199,6258–6301,6579–6600,6611–6638,6843–6847,6908–6923`, `probe/wifi.c:202–223,654–659`)
4. A completion's nonzero `data_offset` takes precedence over the shared offset. The probe currently uses the per-item offset alone, so a zero item offset with nonzero shared offset would misdecode a completed frame. It cannot hide a producer advance. Stock creates Linux ifidx 0 during attach and handles `WLC_E_IF` for host bookkeeping, including creation for additional interface indices. Check the event's ifidx/bsscfgidx before looking for an interface discrepancy. ARP and ND offloads are protocol-specific host configuration, with suspend-related paths in the reference. The cited ordinary RX path has no prerequisite to enable either for Ethernet delivery. (`dhd_msgbuf.c:8108–8125,8403–8413`, `probe/wifi.c:228–255`, `dhd_linux.c:2522–2574,9374`, `dhd_common.c:6210–6258`)
