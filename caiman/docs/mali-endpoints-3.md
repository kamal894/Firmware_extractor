# Mali-G715 endpoint allocation on caiman

The first patch should reproduce the **firmware-managed** kbase initialization, including the unshifted power-off timer and eviction timer, then submit a queued compute stream with kbase's CS/CSG request and interrupt protocol. The GPL host source establishes those differences and the ownership model. The firmware's decision to grant endpoints remains unverified.

## Ranked causes

1. **Incomplete global configuration and a different power-off timer encoding.** gpu18 writes `19` with the modifier enabled, omits the eviction timer request, and writes an all-ones global IRQ mask ahead of the configuration. kbase uses the raw 800 µs count with `NO_MODIFIER=1` at this frequency, always queues the eviction timer, and programs its specific ACK IRQ mask before ringing. gpu18's `GLB_ACK=0x0e` confirms consumption of the three requests sent, with no evidence about the omitted request or effective timeout. **Inference:** this is the highest-value fidelity fix for the firmware-managed run. A power-off timeout governs idle residency, so the encoding difference alone does not establish why demand never produced an observed grant. [`probe/gpu.c:gpu_first_job:478–501`; `csf/mali_kbase_csf_firmware.c:global_init:1901–1967`; `csf/mali_kbase_csf_firmware.c:convert_dur_to_core_pwroff_count:2303–2356`]
2. **Incomplete stream/notification protocol and the empty-to-runnable transition.** The probe stages CS START before CSG START, but omits both interface ACK IRQ masks and kbase's CS idle bits. It starts with INSERT zero, submits STORE, then republishes the ring with compute after the first batch drains. kbase programs bound streams and their doorbell bits before CSG START. Its normal IRQ handler clears the job latch and acknowledges firmware-originated CS and CSG events. **Inference:** test a prequeued STORE-plus-compute batch to remove the empty/reactivation transition, then test the split submit with IRQ servicing. Idle bits request notifications. The source supplies no evidence that IRQ clearing, notification masks, or periodically re-ringing either doorbell independently unlocks an iterator. The logged boot IRQ stays set, CSG IRQ request is zero at the snapshot, and STATUS_UPDATE and command fetch already succeed. [`probe/gpu.c:gpu_firmware:699–720`; `probe/gpu.c:gpu_first_job:558–621`; `csf/mali_kbase_csf_scheduler.c:program_cs:1857–1920`; `csf/mali_kbase_csf_scheduler.c:program_csg_slot:3126–3209`; `csf/mali_kbase_csf.c:kbase_csf_interrupt:3505–3558`]
3. **Inconsistent ownership in the host-powered comparisons.** The source default for real hardware is coarse demand, with zero scheduler PM flags. The adaptive policy also has zero flags. Always-on sets CORE_KEEP_ON and selects `firmware_hctl_core_pwr=true`, meaning **the host controls shader power**. DT policy and debug overrides can change this default. The host-power register interface is separately selected by POWER_CONTROL, absent on tTUx. On the normal path kbase brings up L2, passes the permitted shader mask via ALLOC_EN, and lets the MCU run tiler/shader power. On the legacy always-on path it requests tiler power (which also powers L2) before the MCU, initializes globals with the desired mask and timeout zero, requests shader power after global ACK on reload, waits for stable READY, then publishes READY via a fresh ALLOC_EN transaction. The initial zero ALLOC_EN used in gpu17 differs from kbase's desired mask. Physical READY alone did not grant endpoints in gpu16/17. **Inference:** replay the complete always-on sequence as an independent control if the default-path patch stalls. [`backend/gpu/mali_kbase_pm_policy.c:kbase_pm_policy_init:41–83`; `backend/gpu/mali_kbase_pm_defs.h:policy flags:652–665`; `backend/gpu/mali_kbase_pm_internal.h:kbase_pm_no_mcu_core_pwroff:882–886`; `backend/gpu/mali_kbase_pm_backend.c:backend initialization:185–189`; `mali_kbase_hwconfig_features.h:base_hw_features_tTUx:132–137`; `backend/gpu/mali_kbase_pm_driver.c:need_tiler_control:1840–1846`; `backend/gpu/mali_kbase_pm_driver.c:kbase_pm_l2_update_state:2165–2210`; `backend/gpu/mali_kbase_pm_driver.c:kbase_pm_mcu_update_state:1359–1440`]
4. **Endpoint reporting or compute demand remains unresolved.** All three runs execute STORE and stop at PC `0x1000a0`. The current count is zero. The GPL field decode of `0x00070707` yields compute 7, fragment 7, tiler 7, even though the input caps tiler at 1. CS output `+0x4c` is zero in the same snapshots, including its compute-resource bit. **Inference:** the group status alone cannot establish that CS0 posted valid compute-iterator demand. Compare fresh snapshots before INSERT and with work pending. If the mismatch persists, try compute-only masks and a one-core cap as diagnostic controls, then check the compute packet, descriptors, AS1 permissions and CPU-to-GPU visibility separately from endpoint admission. gpu16/17 also report raw MMU bit 17 with zero fault details. gpu18 reports raw MMU zero, so that bit does not explain the common symptom. [`probe-log-gpu16.txt:1058–1064`; `probe-log-gpu17.txt:1057–1063`; `probe-log-gpu18.txt:1062–1068`; `csf/mali_kbase_csf_registers.h:CSG_STATUS_EP_REQ fields:1336–1357`; `csf/mali_kbase_csf_registers.h:CS_STATUS_REQ_RESOURCE fields:684–723`; `csf/mali_kbase_csf_csg.c:group status decoding:516–570`; `probe/gpu.c:gpu_first_compute:390–452`]

## Exact writes

Offsets are relative to the named input/output block or GPU MMIO base. Values are 32-bit unless shown as low/high pairs. A request described as **toggle** is a masked write of `ACK XOR mask`, preserving all other input bits. State and level fields take explicit values. Use ordered shared-memory writes before updating doorbell request bits and before ringing MMIO. The hexadecimal timer examples assume the project's 24.576 MHz fallback is the actual timestamp frequency. Use raw CNTFRQ_EL0 or kbase's clock-source fallback for the actual values. ## Scheduler and allocation details

- The tick runs the Linux host's scheduling pass, which places off-slot groups, changes resident priorities when required, and handles suspensions. For a single resident runnable group, initial priority is already in CSG_EP_REQ. kbase uses CSG_REQ.EP_CFG for a later priority change and GLB_DB_REQ as a slot notification bitmap. There is no separate CSG_PRIO write or periodic GLB request in this path. `program_csg_slot` explicitly omits EP_CFG when starting/resuming. [`csf/mali_kbase_csf_scheduler.c:tick_timer_callback:644–667`; `csf/mali_kbase_csf_scheduler.c:scheduler_apply:4489–4553`; `csf/mali_kbase_csf_scheduler.c:schedule_actions:5726–5736`; `csf/mali_kbase_csf_scheduler.c:update_csg_slot_priority:3008–3036`; `csf/mali_kbase_csf_scheduler.c:program_csg_slot:3174–3181`]
- ALLOC_EN is a shader bitmap, not a numeric endpoint count. Initial kbase allocation is the PM-selected mask. Compute/fragment max are min(requested max, popcount of present shader cores), and tiler max is capped at 1. Seven is correct for the full mask. Other endpoint permissions come from the group masks. **Inference:** a compute-only control can zero fragment low/high and OTHER and use `0xf0000001` for one compute endpoint, with a present shader bit in the compute mask. The source exposes per-type limits and no prerequisite to request fragment or tiler for compute. [`backend/gpu/mali_kbase_pm_ca.c:kbase_pm_ca_get_core_mask:144–164`; `mali_kbase_gpuprops.c:GPU property decoding:231`; `csf/mali_kbase_csf_scheduler.c:program_csg_slot:3055–3068,3150–3177`]
- Iterator tracing is optional instrumentation. kbase sets GLB_REQ bit 11 only when the firmware advertises support and DT enables it. This run reports GLB_FEATURES zero. The boot/reinit wait mask includes bit 11 and idle bit 10 for equality, without forcing them on. Idle timer activation happens later when host scheduling permits it, and resume explicitly disables idle before firmware reload. **Inference:** leave idle disabled for the first compute experiment, then test it independently if needed. [`csf/mali_kbase_csf_firmware.c:CSF_GLB_REQ_CFG_MASK:117–120`; `csf/mali_kbase_csf_firmware.c:set_iterator_trace_enable:200–225`; `csf/mali_kbase_csf_firmware.c:iterator_trace_reinit:228–241`; `csf/mali_kbase_csf_firmware.c:idle timer scheduling:3547–3569`; `backend/gpu/mali_kbase_pm_driver.c:kbase_pm_mcu_update_state:1359–1384`]

## Ordered patch plan for gpu.c

1. In `gpu_power_up` retain reset and L2 bring-up for default ownership. In `gpu_firmware` use the reported GLB/CSG/CS interface addresses, record the counter frequency, clear and log the boot IRQ, and add a reusable raw IRQ poll/service path with ordered reads. Log new raw events even while waiting for an ACK. Keep SOI disabled in this initial probe.
2. Replace the gpu18 global batch in `gpu_first_job` with kbase's order: optional valid RTU write (skipped on G715), ALLOC_EN, power-off timer and config, progress timer, SOI config, eviction timer and config, exact ACK IRQ mask, barrier and bell 0. Check full config-mask equality and log actual writes, ACK, fatal status/info and doorbell state. Use the compiled timer defaults where DT values are unavailable. For reinit use the same batch, retaining current level bits and matching the pending configuration before proceeding.
3. Initialize AS1 and fill shader code, descriptors, ring and queue pages before scheduling. Publish INSERT for STORE plus compute before CS START. Program CS request and mask, barrier, stage CSG_DB_REQ bit 0, program CSG permissions and START, barrier, stage GLB_DB_REQ bit 0, barrier, ring once and check both states. Use priority 15 for the single runnable slot. On a separate pass retain the working STORE-only baseline, wait for its extract/idle state and then publish the compute suffix with a fresh, ordered kick.
4. In `gpu_first_compute` sample SHADER_READY/TRANS during the wait to distinguish never-on from on/off between snapshots. Capture GLB/CSG request, ACK and doorbell pairs, CSG IRQ request/ACK, CS request/ACK, PC, resource request, blocked reason, scoreboards, group EP current/request, GPU/MMU fault state and GLB fatal status. Compare a status-update snapshot at an idle baseline with one while RUN_COMPUTE is pending. A successful test needs all 64 IDs, queue progress past RUN_COMPUTE, and a clean fault log. If there is still no grant, test the compute-only, one-endpoint CSG first. If resource demand remains zero, audit packet and descriptor visibility/encoding before treating the group status as proof of iterator demand.
5. Run the complete host-controlled sequence only as a separate control. Compare ALLOC_EN requests, stable READY and EP_CURRENT with the default run. If both paths still stall with genuine CS compute demand, inspect the source-supported platform setup differences, including DT quirks and preboot firmware config hooks. kbase processes firmware entry metadata and applies platform configuration/workarounds before boot, while the probe copies memory sections. This is a follow-up hypothesis, with no identified Pixel-specific mandatory endpoint setting in the reviewed host path.
