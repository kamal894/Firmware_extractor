# Caiman Wi-Fi on iOS 16.5 (20F66)

**Start with the fixed BCM4390 attach path and the existing images.** Run 75 never reached Wi-Fi interface publication. The trimmed System image contains the Settings Wi-Fi pane and its frameworks. The separate Redwood image omits several launch jobs, including configd, which both wifid and Preferences tried to reach.

Evidence below uses `ufslog-75.txt` in the scratchpad, `~/caiman-work/hakios-xnu-kernel` for kernel and userland source, and `fw/caiman` for loader source. Image presence was checked by walking the two APFS catalogs directly. Binary evidence comes from the local 20F66 extraction and dyld cache.

## Interface discovery and PPM

- **wifid matches the infrastructure service by property.** Strings in `/usr/sbin/wifid` occur together as `IOServiceMatched`, `IOPropertyMatch`, `IO80211InterfaceRole`, `Infrastructure`, and the failure format `IOServiceAddMatchingNotification IO80211SkywalkInterface failed`. The implementation notes in `drivers/wifi/hakios.wlan.cpp:7–19` identify the match as `IO80211InterfaceRole = "Infrastructure"` and the subsequent IO80211.framework bind as `IOInterfaceName = "en0"`. wifid also contains distinct `Apple80211Open failed` and `Apple80211BindToInterface failed` formats. Evidence supports the property match. The Skywalk name in the error string alone does not establish a required class. No evidence here establishes an AppleBCMWLANCore, IO80211Interface, IOProviderClass or IONameMatch requirement for wifid discovery. The shim's name match for `wlan` locates its own device-tree provider.
- **The match is already implemented, conditional on attach.** `hakios.sta.c:162–199` installs station ops and emits a power event. `drivers/net/hakios.net.c:215–216,266,411` advertises IEEE 802.11 media, forwards Apple80211 ioctls and calls `HakiosWLANStart`. `hakios.wlan.cpp:59–93,96–110,116–169` registers an `IO80211Controller` (an `IOEthernetController` and `IONetworkController`) with a `HakiosWLAN` child of class `IONetworkInterface`. The child publishes the Infrastructure role, interface/BSD name, unit, type, built-in and primary flags. The controller class and child hierarchy also support SystemConfiguration enumeration, as described at lines 13–19. The child deliberately returns `kIOReturnUnsupported` from `newUserClient`. The cache contains `Falling back to IOCTL path` (subcache `.25`, file offset `0x2107ff3`). The fallback uses socket `SIOCGA80211`/`SIOCSA80211` and kernel events, implemented in `drivers/wifi/hakios.apple80211.c:4–26,597–655,714ff`. Per-client matching inside WiFiKit and MobileWiFi was not independently traced.
- **Run 75 stops before this path.** wifid is running by log lines 3329–3334. BCM4390 announces a 20 s delay at 2197–2198 and reports `WLC_GET_VERSION 4: 0` at 5710–5711. The first field is the command return code. `hakios.bcm4390.c:1004–1023` returns on a nonzero result, before either attach call. The delay also makes late-match handling worth verifying once attach succeeds. Look for `bcm4390: en0 and the station are up`, `HakiosWLAN: a user client of type … is asked for`, and actual power/scan ioctl and event traffic before interpreting the UI.
- **PPM refers to ApplePPM power management.** The exact message at log lines 4728–4729 is in `sysimage/20F66__iPhone10,3_6/dyld_shared_cache_arm64.31` at file offset `0xdb3379`, next to `ApplePPM`, `com.apple.duet.ppm-attr.wifi`, `setupIOKitUserClient` and `admissionCheck` strings. wifid weak-links `/usr/lib/libPPM.dylib` and has `WiFiBatteryMgmt No Battery Power Manager support from CoreOS. WiFi will default to full throttle.` The missing service is evidence about power admission, separate from Wi-Fi interface publication.

## Settings and launch jobs

`/System/Library/PrivateFrameworks/PreferencesUI.framework/Settings.plist` defines row `WIFI` with getter `wifiNetwork:`, bundle `WiFiSettings`, controller `APNetworksController` and `requiredCapabilities = [wifi]`. The System APFS contains that plist, `/Applications/Preferences.app/Preferences` and `/System/Library/PreferenceBundles/WiFiSettings.bundle/WiFiSettings`. The bundle's Info.plist identifies `com.apple.WiFiSettings`. Its Mach-O links MobileWiFi, WiFiKitUI, WiFiKit, IO80211, Preferences, UIKit and libMobileGestalt. The System APFS has the corresponding Wi-Fi framework directories, plus CoreWiFi and WiFiPolicy. Framework code comes from the 20F66 shared cache, installed under `/System/Cryptexes/OS/System/Library/Caches/com.apple.dyld/` (`userland/build.sh:733–748`). The visible summary row alone does not show that the detail controller loaded. Run 75 shows Preferences launch and lookup failures, with no observed WiFiSettings loader or controller failure identifying why the tap did nothing.

The System APFS symlinks `/System/Library/LaunchDaemons` to `/redwood/LaunchDaemons` (`userland/build.sh:660–662`). The stock source plists below are under `sysimage/rootfs/System/Library/LaunchDaemons/`. The APFS catalog of `root-same.apfs` has `/LaunchDaemons/com.apple.wifid.plist` and lacks all five jobs below. A missing bootstrap endpoint is consistent with these omissions. The lookups do not by themselves identify a hard dependency.

## Smallest changes and image limits

1. **For pane and scan, start with no System image additions.** Verify interface publication, late discovery, power and scan completion. Then try adding only `com.apple.configd` to the Redwood job list using `userland/build.sh:106–126,460–468` and `mkjobs.py`. The resulting path is `/redwood/LaunchDaemons/com.apple.configd.plist`. This is the smallest candidate job change supported by both processes' logs.
2. **For saved or secured networks**, add `/redwood/LaunchDaemons/com.apple.securityd.plist` if credential operations fail. For an isolated test of the other logged endpoints, the exact job paths are `/redwood/LaunchDaemons/com.apple.WirelessRadioManager.plist`, `/redwood/LaunchDaemons/com.apple.accountsd.plist` and `/redwood/LaunchDaemons/com.apple.locationd.plist`. Location also requires restoring `/usr/libexec/locationd` from stock 20F66 and adding its manifest entry. The full extraction listing `sysimage/rootfs.slt:7379835–7379838` gives 30,931,872 bytes uncompressed and 12,369,920 bytes packed for that binary. `sysimage/select-system.py:89,147–148` excludes it before the Caiman trim even runs. Its runtime dependency closure was not tested.
3. **Keep the image distinction in mind.** `tools/trim_sysimage.py` moves listed files out of the extraction and removes those paths from the build manifest, preserving `system.manifest.full`. `sysimage/trim.txt` names apps, resources and fonts, with no Wi-Fi pane or core Wi-Fi framework entries. The full manifest represents the pre-Caiman HackiOS selection. Undoing the Caiman trim would still leave the launch-job filter and the earlier locationd exclusion in place.

Boot log 1343, 1359, 1368–1369 and 2047–2063 shows the UFS `super` logical partition `xnusys` read to `0x888000000`, with XNU using `rd=md0`. `probe/xnu.c:30–35,526ff,755–760` loads it at high DRAM base +128 MiB in a 4 GiB XNU window (`probe/platform_caiman.h:63–66`). The loader's resident-image cap is 3,200 MiB after reserving 768 MiB and subtracting the 128 MiB offset. The pre-trim HackiOS image fits that size check but exceeds the documented ~1,848 MiB of space in the current partition layout. The stock raw APFS exceeds the loader cap. Neither image by itself supplies a working Caiman registry service or selects additional Redwood launch jobs.

## Remaining blockers to distinguish

- **Identity/capability.** Log 2052, 2135 and 2211 show the iPhone identity, D22AP and iPhone10,3. `probe/identity.h` carries a `wifi-chipset` property, `probe/xnu.c:507` emits `mac-address-wifi0`, and the runtime shim writes `wlan/local-mac-address` if it finds the node (`hakios.wlan.cpp:118–143`). Seeing the Settings row suggests the plist's basic `wifi` capability gate passed. The tap-time capability values were not observed. Log 5433 shows MobileGestaltHelper had a wifid client connection. A wrong hardware-capability answer or a missing `wlan` provider remains a hypothesis, secondary to the observed attach failure.
- **Entitlements and sandbox.** The extracted wifid signature contains `com.apple.wifi.manager-access`, `com.apple.private.system-keychain`, and IOKit user-client allowances naming `IO80211APIUserClient`. The quoted launchd failures are error 3, and the log provides no identified wifid/Preferences sandbox or signing denial explaining the tap. A user-client open refusal from HakiosWLAN is expected by design. After attach, distinguish an intentional refusal followed by ioctl fallback from an absent match, unsupported ioctl, or missing completion event.
